# Граф процессов СМК — минимальная модель (черновик v0.1)

> Статус: **черновик, основа для правил, алгоритмов и промтов**. Утверждено human как отправная точка 02.10.2026 (D-044).
> Код (`core/*`, `scripts/*`) по этой модели ещё **не менялся** — это отдельная задача уровня `high`.

## Зачем

Задача следующего этапа — семантический и логический анализ текста документов СМК: найти в тексте узлы и рёбра графа процессов и собрать из них схему, **не додумывая** то, чего в тексте нет (Rule 0). Этот пакет фиксирует:

- какие элементы схемы **обязательны** (без них схема не собирается) и какие **опциональны**;
- какие **рёбра-перемычки** обязательны и как проверяется связность схемы;
- какие атрибуты у элементов, как они называются в Business Studio и в BPMN;
- как извлекать элементы из текста и чего делать нельзя;
- в каком виде экстрактор отдаёт результат.

## Как читать

1. Человек: `01_concept.md` → `03_mapping.md` → `04_catalogs.md` → при необходимости `02_research.md`.
2. Разработчик правил и валидатора: `schema/` + `rules/connectivity.yaml`.
3. Автор промта экстрактора: `rules/extraction.yaml` + `contracts/extraction_output.schema.json`.

Машиночитаемые файлы — источник истины для кода и промтов; markdown объясняет «почему». При расхождении правится YAML/JSON, затем текст.

## Открытые вопросы

- Типы связей BS взяты из справки BS 5; в BS 6/7 названия могут отличаться (`03_mapping.md`).
- Риски: в КД-СТ-161 справочника рисков нет; у практиков риски есть. Оставлены опцией.
- Роль/группа в BS — отдельный класс оргединиц; в нашей модели — уровень ниже подразделения. Как выгружать в BS — решить при экспорте.
- Цели (BSC) в модель не включены: к схеме процесса не нужны; вернуться при работе с показателями.
