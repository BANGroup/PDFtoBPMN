## 1. КАК УСТРОЕНА ОЦЕНКА RAG

RAG-система — это гибрид из retriever (ищет) и generator (отвечает). Оценивать нужно 4 уровня:

### Уровень 1: Retrieval — нашли ли правильные куски?

| Метрика | Что измеряет | Как считать | Инструмент |
|---------|-------------|-------------|------------|
| **Precision@k** | Из k найденных — сколько релевантны? | релевантных_в_top_k / k | Автоматически, нужен ground truth |
| **Recall@k** | Из всех нужных — сколько нашли? | найдено / всего_релевантных | Автоматически, нужен ground truth |
| **MRR** | Как высоко первый правильный результат? | среднее(1/ранг_первого_верного) | Автоматически |
| **nDCG@k** | Качество ранжирования в целом | Учитывает позиции всех результатов | Автоматически |

**Для расчёта нужен ground truth** — набор пар (запрос → список релевантных чанков). Создаём его вручную один раз для тестового набора.

### Уровень 2: Generation — правильно ли используем контекст?

| Метрика | Что измеряет | Как считать | Инструмент |
|---------|-------------|-------------|------------|
| **Faithfulness** | Всё в ответе подтверждено источником? | утверждения_из_контекста / все_утверждения | RAGAS (LLM-judge) |
| **Answer relevance** | Ответ адресует вопрос? | LLM оценивает (0-1) | RAGAS (LLM-judge) |
| **Hallucination rate** | Сколько выдуманного? | галлюцинации / все_утверждения | RAGAS (LLM-judge) |
| **Citation coverage** | Каждое утверждение имеет ссылку? | утверждений_с_ссылкой / всего | Автоматически (regex) |

**LLM-as-judge:** Второй LLM проверяет ответ первого. RAGAS (open source, MIT) делает это автоматически. Не идеально, но масштабируемо — можно запустить на 100 запросов за минуты.

### Уровень 3: End-to-end — пользователю удобно?

| Метрика | Что измеряет | Как считать | Инструмент |
|---------|-------------|-------------|------------|
| **Correctness** | Ответ фактически верен? | Эксперт: да/нет | Ручная проверка |
| **Completeness** | Все аспекты вопроса покрыты? | покрытые / ожидаемые | Ручная проверка |
| **Source traceability** | Ссылки [док, п.X.Y] валидны? | валидных / всех | Автоматически |
| **Latency** | Время от запроса до ответа | P50, P95 | Автоматически (timer) |

### Уровень 4: Domain-specific — специфика СМК

| Метрика | Что измеряет | Как считать | Инструмент |
|---------|-------------|-------------|------------|
| **ProcessSpec accuracy** | roles/activities/flows верны? | Сравнение с экспертной разметкой | Ручная |
| **BPMN validity** | XML валиден, Camunda открывает? | 25+ проверок | Автоматически (validator) |
| **Cross-doc consistency** | Роль определена одинаково везде? | уникальных / упоминаний | Автоматически |
| **Entity extraction F1** | NER: все KPI/роли/дефиниции найдены? | Precision × Recall / (P + R) | Автоматически vs ground truth |

## 4. ИНСТРУМЕНТЫ ТЕСТИРОВАНИЯ

### 4.1 RAGAS (MIT) — автоматическая оценка RAG

```python
# Пример: оценка RAG-ответов через RAGAS

from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
)
from datasets import Dataset

# Подготовить данные
data = {
    "question": ["Кто отвечает за согласование договора?", ...],
    "answer": ["Руководитель ПФМ отвечает за...", ...],
    "contexts": [["п.7.3: Руководитель ПФМ...", ...], ...],
    "ground_truth": ["Руководитель ПФМ согласовывает...", ...],
}
dataset = Dataset.from_dict(data)

# Оценить
results = evaluate(
    dataset,
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
    llm=local_qwen_llm,  # Локальный LLM как judge
)
print(results)
# {'faithfulness': 0.82, 'answer_relevancy': 0.78, ...}
```

## 6. СОЗДАНИЕ GOLD STANDARD

### Кто и когда

**Фаза 0 (параллельно с POC):** Человек + analyst-processspec создают gold разметку для 10 документов. Это инвестиция времени (~2-3 дня), но без неё метрики невозможны.

### Процесс

1. Выбрать 10 документов (разнообразных по типу и объёму)
2. Для каждого — создать `.gold.yaml`:
   - Вручную перечислить роли, activities, KPI, definitions
   - Составить 5 тестовых запросов с ожидаемыми ответами
3. Зафиксировать как fixtures в `tests/fixtures/gold/`
4. Не менять после фиксации (если меняем — новая версия gold standard)

### Объём

- 10 документов × gold ProcessSpec = ~2 дня
- 50 RAG-запросов с ожидаемыми ответами = ~1 день
- Итого: **3 дня работы эксперта**, окупается многократно
