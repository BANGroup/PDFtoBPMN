# Gold Standard: методология создания

> **Подход:** AI генерирует черновик → аналитик проверяет и корректирует  
> **Объём:** 3 документа глубоко + 7 документов поверхностно  
> **Время аналитика:** ~12-15 часов (не 30)

---

## 1. ПОЧЕМУ ПОЛУАВТОМАТИЧЕСКИЙ ПОДХОД

Полностью ручная разметка 10 документов — 20-30 часов. Полностью автоматическая — ненадёжна (мы же строим систему чтобы автоматизировать это). Золотая середина:

```
Документ → LLM (Claude/Qwen) → Черновик Gold.yaml → Аналитик → Корректировка → Gold.yaml
                                                          │
                                     Время аналитика: 30-40 мин/документ (вместо 2-3 ч)
```

**Важный нюанс: черновик генерирует ДРУГОЙ инструмент, не тот что мы будем оценивать.** Если мы используем текущий pipeline (RACI.md → Pipeline.md) как основу gold — мы создаём bias в пользу текущего подхода. Вместо этого: берём сырой текст документа, отдаём в Claude/Qwen напрямую с промптом "извлеки структуру процесса" → получаем независимый черновик.

## 2. ФОРМАТ GOLD-РАЗМЕТКИ

### 2.1 Три уровня глубины

```
УРОВЕНЬ A — ПОЛНЫЙ (3 документа):
  Всё, что может извлечь система:
  ✓ Роли с RACI
  ✓ Все activities с трассировкой
  ✓ Все flows (sequence, conditions, gateways)
  ✓ KPI и формулы
  ✓ Определения и сокращения
  ✓ Перекрёстные ссылки
  ✓ 10 тестовых RAG-запросов с ответами
  Время аналитика: ~2-3 часа / документ (с черновиком AI)

УРОВЕНЬ B — СТРУКТУРНЫЙ (7 документов):
  Основная структура без деталей:
  ✓ Роли (список, без RACI-привязки к каждому activity)
  ✓ Секции и их тип (SubProcess или нет)
  ✓ Определения и сокращения
  ✓ Количество activities в каждой секции (число, не список)
  ✓ 3 тестовых RAG-запроса с ответами
  ✗ Детальные activities, flows, KPI — нет
  Время аналитика: ~40-60 мин / документ (с черновиком AI)
```

### 2.2 Формат файла — Gold YAML

```yaml
# tests/fixtures/gold/РД-Б7.004-05.gold.yaml

meta:
  document_code: "РД-Б7.004-05"
  title: "Управление договорной деятельностью"
  gold_level: "A"                    # A=полный, B=структурный
  annotator: "Иванов И.И."          # Кто разметил
  annotation_date: "2026-04-01"
  review_date: null                  # Дата ревью вторым экспертом (если есть)
  source_file: "input/РД-Б7.004-05.pdf"
  pages: 45
  notes: "Документ с большим количеством таблиц, 2 блок-схемы"

# ─── РОЛИ (обязательно для уровней A и B) ─────────────────────

roles:
  - name: "Руководитель ПФМ"
    source: "п.5.1, стр.5"
    confidence: high                 # high / medium / low
    note: null

  - name: "Юрист"
    source: "п.5.1, стр.5"
    confidence: high
    note: null

  - name: "Инициатор"
    source: "п.5.1, стр.5"
    confidence: medium
    note: "Обобщённая роль, может быть руководитель любого подразделения"

# ─── СЕКЦИИ (обязательно для A и B) ───────────────────────────

sections:
  - number: "7.1"
    title: "Инициирование договора"
    is_subprocess: true
    expected_activities_count: 4      # Для уровня B — достаточно числа
    expected_gateways_count: 1
    key_roles: ["Инициатор", "Руководитель ПФМ"]

  - number: "7.2"
    title: "Подготовка и согласование"
    is_subprocess: true
    expected_activities_count: 6
    expected_gateways_count: 2
    key_roles: ["Юрист", "Руководитель ПФМ", "Инициатор"]

# ─── ACTIVITIES (только уровень A) ────────────────────────────

activities:    # null для уровня B
  - id: gold_act_1
    name: "Формирование потребности"
    section: "7.1"
    source_ref: "п.7.1, абзац 2, стр.8"
    role_R: "Инициатор"
    role_A: "Руководитель ПФМ"
    type: manual_task
    confidence: high

  - id: gold_act_2
    name: "Проверка обоснования"
    section: "7.1"
    source_ref: "п.7.1, абзац 4, стр.9"
    role_R: "Руководитель ПФМ"
    role_A: "Руководитель ПФМ"
    type: manual_task
    confidence: high

  - id: gold_gw_1
    name: "Обоснование достаточно?"
    section: "7.1"
    source_ref: "п.7.1, абзац 5, стр.9"
    type: exclusive_gateway
    branches:
      - condition: "Достаточно"
        target_section: "7.2"
      - condition: "Недостаточно"
        target: gold_act_return
    confidence: high

  - id: gold_act_return
    name: "Доработка обоснования"
    section: "7.1"
    source_ref: "п.7.1, абзац 5, стр.9"
    role_R: "Инициатор"
    type: manual_task
    confidence: medium
    note: "В документе неясно, сколько итераций доработки допускается"

# ─── FLOWS (только уровень A) ─────────────────────────────────

flows:         # null для уровня B
  - from: gold_act_1
    to: gold_act_2
  - from: gold_act_2
    to: gold_gw_1
  - from: gold_gw_1
    to: gold_act_return
    condition: "Недостаточно"
  - from: gold_act_return
    to: gold_act_2
    note: "Возврат на повторную проверку"

# ─── KPI (уровень A, опционально для B) ───────────────────────

kpis:
  - name: "Срок подготовки договора"
    formula: "Дата подписания - Дата инициирования"
    target: "15 рабочих дней"
    source: "п.8.1, стр.30"
    confidence: high

# ─── ОПРЕДЕЛЕНИЯ (обязательно для A и B) ──────────────────────

definitions:
  - term: "ПФМ"
    definition: "Подразделение финансового менеджмента"
    source: "п.3, стр.4"

  - term: "Договор"
    definition: "Соглашение двух или нескольких лиц..."
    source: "п.3, стр.4"

# ─── ПЕРЕКРЁСТНЫЕ ССЫЛКИ (обязательно для A и B) ──────────────

references:
  - to_document: "КД-РГ-039-05"
    context: "Претензионно-исковая работа"
    source: "п.7.8, стр.25"

# ─── ТЕСТОВЫЕ RAG-ЗАПРОСЫ (обязательно для A и B) ─────────────

rag_tests:
  # --- Уровень A: 10 запросов, уровень B: 3 запроса ---

  - id: q1
    query: "Кто отвечает за согласование договора в РД-Б7.004-05?"
    type: точечный_факт
    expected_sections: ["п.7.3", "п.7.4"]       # Где искать ответ
    expected_answer_keywords:                     # Ключевые слова в ответе
      - "Руководитель ПФМ"
      - "Юрист"
    expected_answer_must_not_contain:              # Чего не должно быть
      - "Директор"                                # Нет в документе
    difficulty: easy

  - id: q2
    query: "Какие KPI установлены для договорного процесса?"
    type: перечисление
    expected_sections: ["п.8.1"]
    expected_answer_keywords:
      - "Срок подготовки"
      - "15 рабочих дней"
    difficulty: medium

  - id: q3
    query: "Что происходит при несоответствии документов при инициировании?"
    type: процессный
    expected_sections: ["п.7.1"]
    expected_answer_keywords:
      - "возвращает"
      - "доработку"
      - "Инициатор"
    difficulty: medium

  - id: q4
    query: "Какие документы ссылаются на РД-Б7.004-05?"
    type: перекрёстный
    expected_sections: []                         # Ответ из других документов
    expected_answer_keywords:
      - "КД-РГ-039-05"                          # Из references других документов
    difficulty: hard

  - id: q5_negative
    query: "Описан ли процесс управления рисками в РД-Б7.004-05?"
    type: негативный
    expected_sections: []
    expected_answer_keywords:
      - "не описан"                              # Или "не найдено"
    difficulty: easy                              # Но важно: не галлюцинировать

# ─── АННОТАЦИИ АНАЛИТИКА ──────────────────────────────────────

annotator_notes:
  - "Раздел 7.5 (Валютный контроль) слабо структурирован, roles неочевидны"
  - "В п.7.2 есть блок-схема, но текст описывает процесс подробнее"

# ─── ОЦЕНКА СЛОЖНОСТИ ДОКУМЕНТА ───────────────────────────────

complexity:
  total_sections: 8                   # Разделов верхнего уровня
  total_subsections: 24               # Подразделов
  estimated_activities: 35            # Примерное количество задач

  graphics_count: 2
  has_tables: true
  tables_count: 5
  cross_references_count: 3
  difficulty_rating: medium           # easy / medium / hard
```

## 3. ПРОЦЕСС СОЗДАНИЯ GOLD STANDARD

### Фаза 1: Подготовка (1 день)

```
Шаг 1.1: Выбрать 10 документов

Критерии выбора:
  - Разнообразие типов: РД, КД, ДП, СТ, РГ
  - Разнообразие объёмов: малый (<30 стр), средний (30-80), большой (>80)
  - Наличие: таблицы, графика, перекрёстные ссылки
  - Есть готовые артефакты: для 3-5 документов уже есть RACI.md + BPMN

Предложение по распределению:

УРОВЕНЬ A (полный, 3 документа):
  1. РД-Б7.004-05 — договоры (уже есть RACI+BPMN, средний объём)
  2. КД-РГ-039-05 — претензии (уже есть RACI+BPMN, много ветвлений)
  3. Один крупный документ (>80 стр) с графикой

УРОВЕНЬ B (структурный, 7 документов):
  4-10. Разнообразные: ДП, СТ, РГ, разные процессные группы (М, Б, В)

Шаг 1.2: Подготовить шаблоны
  - Скопировать Gold YAML шаблон для каждого документа
  - Заполнить meta-секцию
```

### Фаза 2: Генерация черновиков (автоматически, 2-3 часа)

```
Шаг 2.1: Извлечь текст документов
  Если есть OCR.md → использовать
  Если нет → прогнать через Docling (параллельно с POC)

Шаг 2.2: Сгенерировать черновики через LLM
  Инструмент: Claude API (`claude-sonnet-4-6`) — программный вызов
  НЕ использовать текущий pipeline (чтобы избежать bias)

  Промпт для уровня A:
  """
  Прочитай текст корпоративного документа СМК.
  Извлеки и верни в формате YAML:
  1. Все роли, упомянутые в документе (с указанием раздела)
  2. Все задачи/действия по каждому разделу (с цитатой из текста)
  3. Условия ветвления (если...то...иначе)
  4. Последовательность шагов
  5. KPI и показатели (если есть)
  6. Определения и сокращения (из раздела 3-4)
  7. Ссылки на другие документы

  Формат: [вставить YAML-схему]
  ВАЖНО: Если информация не найдена — ставь null, не выдумывай.
  """

  Промпт для уровня B:
  """
  Прочитай документ. Извлеки:
  1. Все роли
  2. Список разделов с оценкой количества задач в каждом
  3. Определения и сокращения
  4. Ссылки на другие документы
  """

Шаг 2.3: Конвертировать в Gold YAML
  Скрипт: scripts/gold/generate_draft.py
  Вход: LLM output (текст)
  Выход: draft Gold YAML с confidence: "ai_draft" для всех полей
```

### Фаза 3: Экспертная верификация (8-10 часов аналитика)

```
Шаг 3.1: Инструктаж аналитика (30 мин)
  - Объяснить формат Gold YAML
  - Показать пример заполненного файла
  - Объяснить поле confidence (high/medium/low)
  - Правило: лучше пропустить, чем додумать

Шаг 3.2: Верификация уровня A (3 × 2ч = 6 часов)
  Аналитик для каждого документа:
  1. Открывает PDF документа + draft Gold YAML рядом
  2. Проходит по каждой секции:
     - Роли: правильно? добавить пропущенные? убрать лишние?
     - Activities: все ли шаги? правильно ли сформулированы?
     - Flows: правильный порядок? условия ветвления?
     - Source references: точные ли ссылки на пункты?
  3. Ставит confidence: high/medium/low для каждого элемента
  4. Добавляет annotator_notes — что неясно, где документ неоднозначен
  5. Составляет 10 RAG-запросов с ожидаемыми ответами

Шаг 3.3: Верификация уровня B (7 × 30мин = 3.5 часа)
  Аналитик для каждого документа:
  1. Проверяет: роли корректны?
  2. Проверяет: секции правильно определены?
  3. Проверяет: количество activities примерно верное?
  4. Проверяет: определения корректны?
  5. Составляет 3 RAG-запроса
```

### Фаза 4: Финализация (1 час)

```
Шаг 4.1: Валидация YAML
  python -m scripts.gold.validate tests/fixtures/gold/

Шаг 4.2: Статистика
  - Всего entities: N ролей, M activities, K definitions
  - Средний confidence: X%
  - Покрытие: Y% разделов имеют activities

Шаг 4.3: Коммит в git
  git add tests/fixtures/gold/
  git commit -m "Gold Standard v1.0: 3A + 7B documents, 50 RAG queries"

Шаг 4.4: Заморозка
  Gold Standard v1.0 — не меняется до следующей версии.
  Если находим ошибки — фиксируем в v1.1, а не правим v1.0.
```

## 4. RAG-ЗАПРОСЫ: ТАКСОНОМИЯ И ПРИМЕРЫ

### 4.1 Типы запросов (50 штук)

```
РАСПРЕДЕЛЕНИЕ:

Тип              Кол-во  Что тестирует           Пример
──────────────────────────────────────────────────────────────────────
Точечный факт    15      Precision, faithfulness  "Кто утверждает договор?"
Перечисление     10      Recall, completeness     "Все KPI для процесса Б7"
Перекрёстный     8       Graph traversal          "Какие документы ссылаются на X?"
Процессный       7       Flow understanding       "Опиши процесс от начала до конца"
Сравнение        5       Multi-document           "Сравни определение X в A и B"
Негативный       5       Hallucination resistance "Есть ли Y в документе Z?" (нет)
──────────────────────────────────────────────────────────────────────
Итого:           50
```

### 4.2 Формат запроса в Gold

```yaml
rag_tests:
  - id: q01
    query: "Кто отвечает за согласование договора?"
    type: точечный_факт
    difficulty: easy
    target_documents: ["РД-Б7.004-05"]          # Где искать
    expected_sections: ["п.7.3", "п.7.4"]       # Конкретные разделы
    expected_answer_keywords:                     # Должно быть в ответе
      - "Руководитель ПФМ"
    expected_answer_must_not_contain:              # Не должно быть
      - "Генеральный директор"
    expected_citations:                            # Ожидаемые ссылки
      - "РД-Б7.004-05, п.7.3"
    evaluation_criteria:
      correctness: "Ответ называет правильную роль"
      completeness: "Упоминает этап согласования"
```

### 4.3 Оценка ответа (как scoring)

```
Для каждого RAG-ответа — 4 оценки:

1. CORRECTNESS (0 / 0.5 / 1):
   0   — фактически неверно
   0.5 — частично верно (есть правильное + есть ошибка)
   1   — фактически верно

2. COMPLETENESS (0 / 0.5 / 1):
   0   — ответ не покрывает вопрос
   0.5 — покрывает частично
   1   — покрывает полностью

3. CITATION_QUALITY (0 / 0.5 / 1):
   0   — нет ссылок или ссылки неверные
   0.5 — есть ссылки, но неточные (раздел указан, абзац нет)
   1   — точные ссылки [документ, п.X.Y]

4. HALLUCINATION (0 / 1):
   0   — нет галлюцинаций
   1   — есть информация, которой нет в документе

Итого на запрос: score = (correctness + completeness + citation) / 3
                 при hallucination=1 → score = 0 (штраф)
```

## 5. ИНСТРУМЕНТЫ АВТОМАТИЗАЦИИ

### 5.1 Генератор черновиков

```python
# scripts/gold/generate_draft.py

"""
Генерирует черновик Gold YAML из текста документа.
Использует Claude API (`claude-sonnet-4-6`) для извлечения структуры.
НЕ использует текущий pipeline — независимый инструмент.

Использование:
  python -m scripts.gold.generate_draft \
    --input input/РД-Б7.004-05_OCR.md \
    --output tests/fixtures/gold/РД-Б7.004-05.draft.yaml \
    --level A \
    --llm qwen  # или claude
"""
```

### 5.2 Валидатор Gold YAML

```python
# scripts/gold/validate.py

"""
Проверяет Gold YAML:
  - Schema validation (все обязательные поля)
  - Role references: все role_R ссылаются на существующую роль
  - Activity references: все flow targets существуют
  - Section coverage: есть activities для каждой секции
  - RAG tests: минимум 3 (B) или 10 (A) запросов

Использование:
  python -m scripts.gold.validate tests/fixtures/gold/
"""
```

### 5.3 Scorer для RAG

```python
# scripts/gold/score_rag.py

"""
Сравнивает ответы RAG-системы с Gold-ожиданиями.

Автоматические метрики:
  - keyword_match: expected_answer_keywords ∩ actual_answer
  - citation_validity: ссылки существуют в документе
  - must_not_contain: проверка отсутствия запрещённого

Полуавтоматические (RAGAS):
  - faithfulness, relevance, context_precision

Ручные (аналитик заполняет):
  - correctness, completeness, hallucination

Использование:
  python -m scripts.gold.score_rag \
    --gold tests/fixtures/gold/ \
    --answers output/rag_answers.json \
    --report output/metrics_report.md
"""
```

## 6. TIMELINE СОЗДАНИЯ GOLD STANDARD

**Выполняется ПАРАЛЛЕЛЬНО с Фазой 0 (POC).** Разработчик делает POC, аналитик — Gold Standard. Общий timeline Фазы 0 = 5 рабочих дней.

```
День 1:
  [Разработчик] POC Docling setup
  [Аналитик]    Выбрать 10 документов, подготовить шаблоны
  [Авто]        Запустить generate_draft.py (Claude API)

День 2:
  [Разработчик] POC Docling тестирование
  [Аналитик]    Верификация 3 документов уровня A

День 3:
  [Разработчик] POC LightRAG
  [Аналитик]    Верификация 7 документов уровня B

День 4:
  [Разработчик] POC Qwen VLM
  [Аналитик]    Составление 50 RAG-запросов

День 5:
  [Разработчик] Отчёт POC
  [Аналитик]    Валидация Gold YAML, коммит
  [Вместе]      Governance gate: решение по компонентам
  
ИТОГО аналитик: ~12-15 часов за 4 дня
```
